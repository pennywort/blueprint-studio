# Команда: check-state

Ты аудитор. Сверяешь файл `PROJECT_STATE.md` в корне проекта с фактическим состоянием репозитория и выдаёшь отчёт о расхождениях (drift report).

## ЖЕЛЕЗНЫЕ ПРАВИЛА

1. **READ-ONLY.** Тебе ЗАПРЕЩЕНО изменять любые файлы, включая сам PROJECT_STATE.md. Никаких правок, никаких «заодно поправлю». Только отчёт.
2. **Ничего не выдумывать.** Каждое утверждение в отчёте опирается на конкретный результат конкретной команды. Указывай, чем проверено.
3. Не исправляешь — только находишь. Исправление делает команда `/update-state` или человек.

## Шаг 1. Сводка PROJECT_STATE.md (НЕ читай файл целиком — 72 КБ)

Выполни `npm run state:summary` и `npm run state:check`. Детали нужной секции — `npm run state:section -- <id>` (например `4.1`). Выпиши проверяемые утверждения:

- §2 STACK: пакеты, версии, статусы (installed/planned)
- §4.1 DONE: что заявлено как реализованное
- §4.2 NOT DONE: что заявлено как отсутствующее
- §5 INVARIANTS: статусы
- §7 NEXT STEPS: открытые задачи
- §8 EPICS: статусы и проценты

## Шаг 2. Собери факты из репозитория

Выполни (все команды read-only):

1. `git log --oneline -15`
2. `git status --short`
3. `npm run state:check` уже сверил §2 STACK с package.json — `cat package.json` не нужен
4. `git ls-files src/<каталог>` — только по каталогам, упомянутым в проверяемом пункте (не `ls -R src/`)
5. Для каждого утверждения §4.1/§4.2 про конкретные файлы — проверь `ls` + содержимое (stub ≠ реализация: если файл существует, но функция пустая/no-op — это расхождение)
6. Для §5 — проверь наличие и содержимое файлов инвариантов

## Шаг 3. Сверь и классифицируй

Каждый пункт отчёта — одна из категорий:

- ✅ MATCH — документ соответствует реальности (перечисли кратко, без деталей)
- ⚠️ DRIFT — расхождение. Формат: `[секция] заявлено: X | фактически: Y | проверено: <команда>`
- ❓ UNVERIFIABLE — проверить невозможно из репо (например, «процент готовности эпика», open questions). Перечисли, что нужно решение владельца
- 🆕 NOT DOCUMENTED — в репо есть факт, которого нет в PROJECT_STATE (новый пакет, новый каталог)

## Шаг 4. Формат отчёта

```
CHECK-STATE REPORT — <дата>
Документ UPDATED: <дата из шапки PROJECT_STATE.md>
HEAD: <git log -1>

⚠️ DRIFT (N):
  1. ...

🆕 NOT DOCUMENTED (N):
  1. ...

❓ UNVERIFIABLE (N):
  1. ...

✅ MATCH: N утверждений подтверждено.

ВЕРДИКТ: CLEAN | DRIFT DETECTED — рекомендуется /update-state
```

## Шаг 5. Стоп

Отчёт выдан — работа закончена. НЕ предлагай исправить файлы сам, НЕ правь ничего. Скажи: «Для исправления запустите /update-state».
