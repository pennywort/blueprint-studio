# INSTRUCTIONS — создание 34 OpenSpec-changes по готовому коду

> Читай этот файл целиком в начале КАЖДОЙ сессии и работай строго по нему.
> Если что-то неясно, остановись и спроси владельца. Контекст маленький: читай только то, что нужно для текущей задачи.

## 0. Задача

Код проекта уже готов и лежит в репозитории. **Код не трогай.**
Для каждой из 34 задач (`.replay/tasks/NN-<id>.md`) создай один OpenSpec change **своим скиллом создания change**.
Формат файлов, нумерацию и структуру задаёт скилл, а этот протокол задаёт только содержание и порядок.
Формулируй так, будто задача ещё предстоит («система ДОЛЖНА…»). Описывать нужно только то, что реально есть в коде.

## 1. Что такое change

- **Один файл задачи = один change.** Их ровно 34, порядок по номерам. Не дроби, не объединяй и не добавляй новые.
- Мелочи (стрелки, цвета, отступы, fix/revert, замечания приёмки) — это пункты `tasks.md` своего change, а не отдельные changes.
- Пункты из раздела «Не входит» не описывай.

## 2. Сессия = одна задача

Начало сессии:

1. Прочитай этот файл.
2. В `.replay/PROGRESS.md` найди «Текущая задача» и работай только над ней.
3. Прочитай файл задачи `.replay/tasks/NN-*.md`.

Работа:

1. Сверь каждый пункт «Состава» с кодом: найди упомянутые символы grep-ом, файлы из «Где проверять по коду» открой только нужным диапазоном.
2. Пункт не подтверждается кодом — не пиши его как требование, вынеси в Open Questions.
3. Запусти свой скилл создания change. Передай ему:
   - имя change: поле `change id`;
   - зачем: раздел «Цель»;
   - что меняется: «Состав»;
   - non-goals: «Не входит»;
   - мелочи: подпункты задач;
   - номера: поле «Номера» (T-xxx, ADR, D, R) должно попасть в документы там, где скилл предусматривает ссылки.
4. Полный текст ADR возьми точечно из `PROJECT_STATE.md` §3 (`grep -n "ADR-19" PROJECT_STATE.md` и чтение этой строки).
5. Если у скилла есть проверка (например `openspec validate <id> --strict`), запусти её, она должна пройти.

Конец сессии:

1. В `PROGRESS.md` поставь статус `done`, запиши номер или путь, который дал скилл, переведи «Текущая задача» на следующую и допиши строку в журнал.
2. Если «Коммитит агент: да», закоммить только папку этого change. Формат сообщения — в `.replay/COMMIT-REFS.md`, номера возьми из строки задачи. Если «нет», ничего не коммить.
3. Напиши владельцу ровно: `Задача NN готова. Очисти контекст (/clear) и отправь: «Продолжи по .replay/INSTRUCTIONS.md».`
4. Остановись. Следующую задачу в этом контексте не начинай.

Если контекст заполнен больше чем на 70% посреди задачи — остановись, запиши в «Заметки», что сделано и что осталось, и попроси очистить контекст.

## 3. Запрещено

- Менять что-либо кроме папки change и `.replay/PROGRESS.md`.
- Писать или запускать тесты. Читать `node_modules/`, `dist/`, `package-lock.json`, `docs/archive/`, `*.disabled`, а также `PROJECT_STATE.md` целиком (только точечно).
- Выдумывать поведение, которого нет в коде или документах.
- Описывать в change возможности других задач. Ссылаться на них можно («подробно — в change `<id>`»).
- `git push --force`, push в `main`/`master`, merge. Это делает владелец.

- [ ] проверка скилла пройдена (если есть);
- [ ] `PROGRESS.md` обновлён, владельцу отправлено сообщение конца сессии.
