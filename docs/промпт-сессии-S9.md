Специфика задач этой сессии (порядок: проводка состояния → T-031 → T-036 → T-032):

- T-031 (кастомные узлы). Реестр nodeTypes: home/subScenario → ScenarioNode

  чип «Одностраничная»/«Степперная», корзина; шаги — горизонтальные колонки
  внутри узла, у каждого шага заголовок, корзина и «+»). Строка-элемент
  ElementCard: иконка, основной/доп. текст, чип типа, source-handle на правом
  краю (D9). Карточки — Flamingo Card/CardContent. Расширь CanvasNodeData в
  graph-flow-adapter.ts данными для рендера (элементы узла, шаги формы) —
  это штатное развитие адаптера T-030; существующий graph-flow-adapter.test.ts
  при этом почини точечно. Корзины и «+» в этой сессии только рисуются —
  обработчики добавления/удаления узлов и элементов НЕ подключай
  (это T-034, сессия S10). Узлы EditorCanvas получает из graphToFlow.

- T-036 (слоистый layout-движок, D7/D13). Два уровня:
  * Глубины — чистая функция в domain (например, src/domain/graph-depths.ts):
    computeGraphDepths(graph) → глубина каждой страницы = длина кратчайшего
    пути от корня (BFS по links: ребро элемент→страница считается ребром
    «страница-владелец элемента → страница-цель»). Главная, если есть, —
    глубина 0; Главная необязательна (D8): корни — узлы без входящих рёбер,
    каждый несвязанный подграф раскладывается от своего корня. Формы — на
    общих основаниях (D12).
  * Позиции — computeLayout(graph) в presentation/features/canvas/: колонка =
    глубина, Y внутри колонки — по orderIndex (D13), размеры/отступы —
    константами из темы/макетов. Результат скармливается в graphToFlow через
    параметр positions.
  * Правило запрета перескока (D7) — внутри команд ConnectElements /
    ReconnectElements (application): после структурного создания/переназначения
    связи пересчитай глубины на черновике через computeGraphDepths; если цель
    оказалась НЕ в слое «глубина источника + 1» — перенеси её в этот слой,
    поставив в конец колонки (orderIndex цели = следующий за максимальным
    в целевой колонке). Метки «T-036» в командах замени реализацией.
    При DisconnectElements узел остаётся на своём orderIndex (уже так).
    Существующие тесты connect/reconnect (S8) при расширении поведения
    почини точечно.
  * Переупорядочивание внутри слоя — вертикальный drag узла (ограничение по
    оси X или свой механизм), результат — команда ReorderInLayer; порядок
    после drag определяй через flowNodesToLayerOrder из адаптера.

- T-032 (рёбра и связи). Source-handle — на карточке элемента (ElementCard),
