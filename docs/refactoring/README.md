## Порядок работы агента (для любого плана)

1. `git status -sb`; работа в рабочей ветке (AGENTS.md §4, Git).
2. Прочитай этот README и ОДИН файл плана; код — только файлы, названные в шаге
   (сначала поиск, потом чтение диапазона, AGENTS.md §6).
3. Один шаг = один коммит `refactor(<область>): <ID> — <что>` (conventional, по-русски).
4. Поведение для пользователя НЕ меняется, если шаг явно не говорит иное. Нашёл расхождение
   или неясность — не выбирай сам, спроси владельца.
5. Тесты не пишем и не запускаем (AGENTS.md §4). Проверка — `npm run ui` по сценариям шага;
   `verify` + `rules` прогонит pre-commit.
6. После шага: в файле плана отметь шаг ✅ (дата, коммит), здесь — статус плана; merge (§7);
   в ответе владельцу — что сделано и какие сценарии проверены (AGENTS.md §0, лимиты объёма).

## Общие правила (кратко, полный текст — AGENTS.md §4/§4a)

- Мутации графа — только командами `CommandBus`; слои `domain → application → infrastructure →
presentation`; внешние контракты — за портами `application/ports`.
- UI — только `@blueprint-vendor/*`; цвета — из темы; комментарии по-русски со ссылкой на ID шага.
- «Одно понятие — один механизм»: нашёл ещё один параллельный механизм — допиши его в план,
  а не латай молча.
