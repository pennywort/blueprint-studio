# R-PERF. Производительность канваса и стилей на больших картах [owner 2026-10-20]

Общий порядок работы — [README.md](README.md). Документ — результат ревью
`/react-flow-advanced-best-practices` + разбор CSS и компонентов. **Код не менялся.**

## 0. База ревью

- `@xyflow/react` **12.12.0** (точная версия, `package.json`); React 19.3; UI — MUI v4 под шимом Flamingo.
- Официальные источники (reactflow.dev, релизы xyflow) **недоступны** из сессии (прокси 403):
  ревью построено на локальных playbook'ах скилла (`references/performance-playbook.md`,
  `advanced-feature-playbook.md`) и чтении кода. Перед шагами R-PERF-5/9 — сверить с
  release notes 12.12+ (снапшот: `scripts/sync_react_flow_sources.py`, см. SKILL.md).
- Стенд: `/#/editor?project=stress`, по умолчанию 4×25×6 → ~121 узел, ~1105 карточек
  (комментарий `canvas-interaction.tsx`). «Большая карта» в этом плане — ×5…×10 от стенда.

## 1. Что уже сделано правильно (не трогать)

| Практика RF                                   | Где                                                                                       |
| --------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `nodeTypes`/`edgeTypes` — константы модуля    | `nodes/node-types.ts`, `canvas-edges.tsx`                                                 |
| Узлы, рёбра, карточки, канвас — `memo`        | `ScenarioNode`, `FormNode`, `FormStepColumn`, `ElementCard`, `EditorEdge`, `EditorCanvas` |
| Эфемерное состояние вне `data` узлов          | `canvas-interaction.tsx` (селекторы `useSyncExternalStore`)                               |
| Структурное разделение результата адаптера    | `graph-flow-adapter.ts` `share/shareFlow`                                                 |
| Сохранение `measured` между пересчётами       | `editor-canvas.tsx` `withMeasured`                                                        |
| Пакетирование замеров за кадр                 | `use-canvas-nodes.ts` `useMeasuredBatch`                                                  |
| Стабильные обработчики в пропсах ReactFlow    | `editor-canvas.tsx` (ревью P3) — **с исключением, см. F1**                                |
| Ввод атрибутов — одна команда на 300 мс       | `attributes/use-buffered-props.ts`                                                        |
| Нет динамических `makeStyles(props)`, нет hex | весь `src/presentation`                                                                   |

## 2. Находки

Вес: 🔴 заметно на большой карте, 🟡 средний, ⚪ гигиена/поддержка.

### React Flow / канвас

| ID  | Вес | Находка                                                                                                                                            | Почему важно на большой карте                                                                                                                                                               |
| --- | --- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | 🔴  | В клик-режиме связи `clickLine` меняется на каждый `pointermove`; от него зависят `cancelClickConnection` → `handlePaneClick` (проп `onPaneClick`) | Новый проп ReactFlow на каждый кадр → обновление стора RF → все подписчики (тысячи handles) перепроверяют селекторы; плюс ре-рендер `CanvasInner` на кадр. Ровно то, что ревью P3 запрещало |
| F2  | 🟡  | `onNodeDrag` на каждый кадр: `findColumnCandidate` строит Map и колонки по всем узлам; `setDropZone` всегда новым объектом                         | O(N) на кадр drag + ре-рендер `CanvasInner` на кадр даже без смены колонки                                                                                                                  |
| F3  | 🟡  | `reportNodeSizes`: `previousFlowRef.current.nodes.find(...)` внутри цикла по замерам                                                               | O(N²) на загрузке/массовом перемере (N узлов в одной пачке)                                                                                                                                 |
| F4  | 🟡  | `propsNodes → useEffect → setNodes`: второй рендер ReactFlow после каждой команды, между ними — кадр со старыми узлами                             | 2× рендер дерева RF на команду; возможное «мигание» кадра                                                                                                                                   |
| F5  | 🔴  | Каждая команда: полный `computeLayout` + `graphToFlow` + глубокий `share` всего графа + `collectViolations(graph)`                                 | Стоимость команды растёт линейно с картой; при ×10 стенда — десятки мс на любое действие                                                                                                    |
| F6  | 🟡  | `ScenarioNode`: на каждый узел свой `ResizeObserver` + `getBoundingClientRect` по каждому слоту в `useLayoutEffect`                                | Сотни наблюдателей и чтений layout на загрузке; RF уже наблюдает размеры узлов                                                                                                              |
| F7  | ⚪  | Виртуализации (`onlyRenderVisibleElements`) нет — и она конфликтует с раскладкой по замерам (N12): невидимые узлы не измеряются                    | Потолок масштаба: весь граф всегда в DOM. Решение — только после R-PERF-5 (см. §5)                                                                                                          |
| F8  | ⚪  | Отмена клик-связи — запись во внутренний стор RF (реестр подмен п.7)                                                                               | Риск поломки при обновлении RF; проверять сценарий при каждом апгрейде                                                                                                                      |

## 3. Риски оптимизации (особенно на больших картах)

| Риск                                                                                              | Где                                                        | Как снять                                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Устаревший `measured` → узлы «прыгают», рёбра крепятся к старым handles                           | F4, F5, F6 — любой обход `withMeasured`/`useMeasuredBatch` | Не трогать контракт замеров; проверка: загрузка стенда, добавление/удаление карточки, reorder                                                                                                                              |
| Петля «замер → раскладка → замер»                                                                 | F3, F6 (допуск 1px в `useMeasuredBatch`)                   | Сохранять допуск и пакетирование; на стенде считать число раскладок на загрузке (было 44 → должно остаться ≤ текущего)                                                                                                     |
| Инкрементальный пайплайн отдаёт устаревший кусок графа (кэш по identity страницы)                 | F5                                                         | Кэш только по объектам immer (структурное разделение гарантирует новый объект при изменении); глобальные зависимости (связи между страницами, нарушения кросс-страничных инвариантов, глубины) — не кэшировать по странице |
| Нарушения инвариантов пропускаются при частичной проверке                                         | F5                                                         | `collectViolations` оставить полным, но вне горячего пути (после кадра / idle) — или инкрементальным только с решением владельца                                                                                           |
| Смена порядка/приоритета рамок меняет вид выделения, ошибок, целей                                | S2, S3                                                     | Сначала таблица состояний и приоритетов (§4a), сверка с макетами; проверка — `npm run ui` по всем 4 состояниям                                                                                                             |
| Облегчённая карточка расходится с целевой ДС                                                      | C1                                                         | Решение владельца: карточки канваса — «рисунок» (div + `theme.typography`) или компоненты Flamingo. Токены — только из темы                                                                                                |
| `base.css` вместо `style.css` ломает служебные стили RF (pane, handles, selection rect, controls) | S4                                                         | Переносить недостающее в scoped `react-flow-theme-styles.ts`; проверка pan/zoom/выделение рамкой/миникарта                                                                                                                 |
| Курсор-прицел пропадает над узлами без `!important`                                               | S1                                                         | Прозрачный слой-перехватчик курсора только на время протягивания или `cursor: inherit` для узлов в режиме связи; проверка повторной приёмки 5.1                                                                            |
| Виртуализация ломает раскладку по замерам и поиск/фокус                                           | F7                                                         | Не включать до оценочных размеров невидимых узлов; отдельное решение владельца                                                                                                                                             |
| Обновление RF ломает обход п.7 (клик-связь)                                                       | F8                                                         | Сценарий «клик-связь → Esc → снова клик-связь» при каждом апгрейде                                                                                                                                                         |
| Нет базовых замеров — оптимизация «вслепую»                                                       | все                                                        | Шаг R-PERF-0 обязателен первым; тестов не пишем — замеры вручную через `npm run ui` / профайлер                                                                                                                            |

## 4. Шаги

Порядок: сначала дешёвые и безопасные (1–4), затем стили (6–9), крупное — по решению владельца.
Генерируемость (§4b) у всех шагов: **=** (модель экрана не затрагивается).

## 5. Проверка каждого шага (чек-лист)

- [ ] R-PERF-0 выполнен, замеры «до» записаны; после шага — те же замеры «после».
- [ ] `nodeTypes`/`edgeTypes` по-прежнему константы; пропсы `<ReactFlow>` не меняются на кадр (React DevTools «why did this render»).
- [ ] Число раскладок на загрузке стенда не выросло; узлы не «прыгают» после загрузки.
- [ ] `npm run ui`: связь drag'ом и кликом (+ Esc), reorder и перенос узла между уровнями, dnd карточки и шага, выделение узла/шага/карточки, подсветка ошибки.
- [ ] Миникарта, pan/zoom, fitView поиска (T-050) работают.
- [ ] Отчёт: «точечно / объединил; параллельные механизмы: …» (§4a) и «генерируемость: =».
