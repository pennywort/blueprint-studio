### 4b. Проект R-PERF-6 — единая подсветка сущностей

**Сейчас (параллельные механизмы, §4a AGENTS).** Состояние берётся из 4 источников, рисуется 4 способами:

| Состояние                       | Источник сегодня                                                 | Рисование сегодня                                                                                                          |
| ------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| выделен (узел / шаг / карточка) | `selected` react-flow; стор `selectedStepId`/`selectedElementId` | глобальный селектор по `data-testid` + `:has()` (узел); `stepSelected` (шаг); `cardSelected` border + inset 1px (карточка) |
| ошибка                          | стор `violations`                                                | `nodeClasses.invalid` inset 2px; `cardInvalid` borderColor                                                                 |
| цель dnd / обмена шагов         | локальный state узла (`useElementDropZone`, swap шага)           | `nodeClasses.dropTarget` фон + `outline`                                                                                   |
| зона приёма dnd                 | локальный state узла (`drop`)                                    | `nodeClasses.dndActive` `outline dashed`                                                                                   |
| цель связи под курсором         | `useConnection` react-flow / CSS `:hover` handle                 | `outline -3px` на прозрачном handle                                                                                        |

Приоритет между ними держится специфичностью CSS — сменить его конфигом нельзя.

**Целевая схема — данные → чистая функция → одно значение → одно правило рисования.**

1. **Состояния — флаги в одном сторе.** Всё переносится в `CanvasInteractionStore`
   (`canvas-interaction.tsx`): уже есть выделение и нарушения; добавляются `dropTarget`
   (id сущности под dnd), `dropZone` (id узла, над которым идёт dnd) и `connectHover` (id цели
   связи под курсором — канвас пишет его один раз из `useConnection`, узлы сами на react-flow не
   подписываются). Локальные state подсветки в узлах и CSS `:hover` для рамки удаляются.
2. **Политика — данные (конфиг).** В теме (`editor-theme.ts`, по R-CFG: «геометрия и цвета рамок —
   в теме»), поле `editor.highlight`:

   ```ts
   // Приоритет: первый в списке побеждает. Смена порядка/отключение — правка массива.
   priority: ['connectHover', 'dropTarget', 'dropZone', 'selected', 'invalid'],
   // Вид каждого состояния; цвет — ключ токена темы, не hex. width по виду сущности.
   frames: {
     selected:     { color: 'canvas.edge',           style: 'solid',  width: { node: 2, step: 2, card: 1 } },
     invalid:      { color: 'palette.error.main',    style: 'solid',  width: { node: 2, step: 2, card: 1 } },
     dropTarget:   { color: 'canvas.nodeHoverBorder', style: 'solid', width: 2, fill: 'canvas.nodeHoverBackground' },
     dropZone:     { color: 'canvas.nodeHoverBorder', style: 'dashed', width: 2 },
     connectHover: { color: 'canvas.edgeActive',     style: 'solid',  width: 2 },
   },
   ```

   Новый вид подсветки = запись в `frames` + место в `priority`; ядро не меняется (Open/Closed).
   Проверка формы политики — zod при создании темы.

3. **Разрешение — чистая функция** `resolveHighlight(entity, state, policy): HighlightKind | null`
   (новый файл `features/canvas/highlight/resolve-highlight.ts`): собирает активные флаги сущности
   и возвращает первый по `priority`. Эталон стиля — `domain/layer-depths.ts` (данные + функция).
4. **Подписка — один хук** `useEntityHighlight({ kind: 'node' | 'step' | 'card', id })`:
   `useCanvasInteraction(state => resolveHighlight(...))` возвращает строку — компонент
   перерисовывается только когда меняется ИТОГОВОЕ значение, а не любой флаг (важно для тысяч карточек).
5. **Рисование — одно правило, одна геометрия.** Сущность получает `data-highlight="<kind>"`.
   Общий `makeStyles` (`highlight/highlight-styles.ts`) генерирует правила из `frames`:
   `&[data-highlight="selected"]::after { … }` — абсолютный псевдоэлемент `inset: 0`,
   `border-radius: inherit`, `border: <width> <style> <color>`, `pointer-events: none`.
   Рамка внутри сущности (как сейчас, размер не меняется ни на пиксель), сплошная и пунктирная —
   одним механизмом, `fill` — фон корня. Тень elevation карточки не трогается.
6. **Удаляется:** селектор `.react-flow__node.selected [data-testid^=…]:not(:has(…))`,
   классы `invalid`/`dropTarget`/`dndActive`/`stepSelected`/`cardSelected`/`cardInvalid`,
   `outline` у `editor-target…:hover`. Принимающий handle (ADR-14) остаётся только зоной приёма и
   кружком-маркером «сюда можно» — маркер не рамка, в политику не входит.

**Почему это быстрее на большой карте:** смена подсветки = смена одного атрибута у 1–2 элементов
(пересчёт стилей только их), нет `:has()` и селекторов по префиксу атрибута, нет подписки каждого
узла на стор react-flow; правило `[data-highlight=x]::after` — дешёвый селектор.

**Риски:** вид рамок должен совпасть с текущим (сверка с макетами и `npm run ui` по 5 состояниям);
`::after` не должен перекрыть handles и кнопки (`z-index` ниже их, `pointer-events: none`);
перенос dnd-флагов в стор — тот же поток событий, что сейчас (`dragenter/leave/drop`), без задержки.

**Порядок внутри шага:** 6.1 политика + `resolveHighlight` + хук + стили (без подключения);
6.2 карточка; 6.3 шаг; 6.4 узлы и удаление старых классов/селектора; 6.5 перенос dnd- и
connect-флагов в стор. Каждый подшаг — коммит и `npm run ui`.
