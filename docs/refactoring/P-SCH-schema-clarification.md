## Цель

Точно описать, **из чего состоит схема элемента** и **как проект её дополняет**, чтобы дальше
перестроить редактор на один источник атрибутов. Код в этом проекте не меняется — результат документ
и список вопросов команде фреймворка.

## Архитектура, заданная владельцем (не обсуждается)

```text
пакет фреймворка (element-schemas)  →  слой проекта (blueprint-studio)  →  панель атрибутов
схемы ВСЕХ элементов, все атрибуты     выбрать / сузить / расширить         поле по типу атрибута
                                        атрибуты; добавить свои элементы     (набор типов конечен)
                                        (напр. комментарий-элемент)
```

- База — всегда из пакета; проект её не копирует, а накладывает изменения.
- Слой проекта может: скрыть атрибут, сузить значения (enum), добавить свой атрибут, добавить свой
  вид элемента, задать подписи/секции/условную видимость.
- Типы атрибутов — конечный список; на каждый тип — один редактор в панели.
- Всё, что генератор UI соберёт в страницу, хранится в карте типизированными данными (AGENTS.md §4b).
- Правила — данные/конфиг, не `if` (AGENTS.md §4a, ADR-20).

## Что сделать

1. **Разбор образца.** Все ключи верхнего уровня (`elementType`, `x-category`, `properties`,
   `x-events`, `x-defaults`, `required`, `deprecatedAliases` …) и все формы описания атрибута
   (`type`, `enum`, `oneOf`, `default`, `description`, вложенные объекты). Для каждого — нужен ли
   редактору карты и зачем.
2. **Конечный набор типов атрибутов.** Предложить список (например: строка, многострочный текст,
   число, флаг, один из списка, несколько из списка, список строк, список объектов, ссылка/иконка) и
   правило, как каждая форма JSON Schema сводится к одному типу. Что делать с `oneOf`
   (`width: number | match_parent`) — отдельно.
3. **Формат слоя проекта.** Описать (JSON + zod-эскиз) запись слоя: показать/скрыть, сузить enum,
   подписи, секции, порядок, условная видимость, свои атрибуты, свои виды элементов. Как ловить
   расхождение слоя с пакетом при старте (атрибут исчез из пакета, сменился тип).
4. **Соответствие нынешним 15 видам.** Таблица: наш `kind` ↔ `elementType` пакета (`textField` ↔
   `text-field`?), наши поля ↔ поля пакета (`caption` ↔ `helperText`? `maxLength` ↔ `counter`?).
   Чего нет в пакете → это атрибут слоя проекта или ошибка нашей модели.
5. **Вопросы команде фреймворка** (конституция П2 — формат не додумывать): как получить пакет,
   версионирование, полный список `elementType`, стабильность имён полей, что значат `x-events`.
