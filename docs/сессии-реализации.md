# Сессии реализации: как гонять реализующего агента (GigaCode / Qwen)

> Документ для владельца (не для агента целиком — агенту даётся только промпт его сессии).
> Проблема: у агента мало контекста, весь скоуп грузить нельзя. Решение: **одна сессия = одна маленькая пачка задач**, между сессиями — протокол проверки.

---

## 1. Принципы нарезки

1. **Одна сессия = 1–2 задачи** из декомпозиции, не больше. Сессия заканчивается, когда критерии задач выполнены и проверка пройдена.
2. **Контекст сессии минимален:** в промпт идёт только текст конкретных задач + решения D*, которые они затрагивают + правила проверки. Весь документ декомпозиции целиком НЕ вставлять — дать путь к файлу, пусть читает сам нужные разделы.
3. **Контекст между сессиями переносит `PROJECT_STATE.md`** — агент в новой сессии сначала читает его (и handoff.md), а не историю прошлого чата.
4. **Каждая сессия заканчивается коммитом.** `update-state` работает только с закоммиченным состоянием — без коммита проверка бессмысленна.

## 3. Протокол проверки каждой сессии

> **[Решение владельца 2026-10-10]: тесты не пишутся и не запускаются**
> (конституция §8 П4). Проверка выхода — глазами по критериям задачи;
> `npm run test` из протокола исключён, точечный прогон — только при
> изменении ранее написанного кода с уже существующими тестами.

После того как агент сказал «готово», **не верить** — прогнать:

```bash
npm run lint && npm run build && git status --short
```

Затем, по ролям:

1. **Коммит** — агент коммитит работу (или владелец). Без коммита дальше не идём.
2. **`/check-state`** — аудит: сверяет PROJECT_STATE.md с репозиторием (read-only, ничего не правит). Покажет DRIFT: что заявлено сделанным, но в репо нет / stub вместо реализации. Это и есть основной инструмент «проверить, не наврал ли агент» — check-state смотрит в содержимое файлов, а не в имена.
3. **Приёмка по критериям задачи** — из текста задачи в декомпозиции (столбец «Проверка выхода» выше). Глазами или тестом.
4. **`/update-state`** — фиксирует подтверждённое в PROJECT_STATE.md: выполненное уходит из §7 NEXT STEPS в §4.1 DONE, бампается прогресс эпика. Показывает diff и спрашивает «Применить?» — владелец подтверждает.
5. Следующая сессия стартует с чистого PROJECT_STATE.md.

Если check-state нашёл DRIFT в работе текущей сессии — задача НЕ принята, агенту в той же сессии: «вот расхождения, чини». Если drift в старых секциях — решает владелец, не агент.

## 4. Шаблон промпта одной сессии

```
Ты реализуешь задачи [S-номер]: [T-xxx, T-yyy] эпика 002 canvas-редактора blueprint-studio.

Источники правды (читай в этом порядке):
1. PROJECT_STATE.md — текущее состояние проекта
2. декомпозиция-canvas-редактор.md — ТОЛЬКО §1 (решения D1–D13), §3 (принципы) и тексты задач [T-xxx, T-yyy]
3. handoff.md — правила слоёв (§8.2)

Жёсткие правила:
- Реализуешь ТОЛЬКО перечисленные задачи. Остальное не трогаешь.
- Решения D1–D13 не обсуждаются. Поля панелей не хардкодятся, UI только из Flamingo (включая иконки), цвета только из темы, мутации графа только через CommandBus.
- В тексте задачи есть критерий приёмки — он обязателен.
- [Только для S3: решение владельца по FormStep — <вставить>]

По завершении:
1. npm run lint && npm run build — всё зелёное (тесты не пишем и не запускаем [решение владельца 2026-10-10])
2. git add + commit с сообщением "Epic 002: T-xxx <название>"
3. Отчёт: номер задачи, изменённые файлы, результат проверок, вопросы если есть.
Не запускай /update-state сам — это делает владелец после приёмки.
```

## 5. Что НЕ давать агенту

- Весь документ декомпозиции в промпт — он начнёт делать задачи не по порядку.
- Задачи E5 до завершения E3/E4 (граф зависимостей §5).
- Право запускать `/update-state` самому — иначе агент будет «подтверждать» свою же работу.
- Незакоммиченную работу на проверку — check-state по коммитам.

## 6. Известные исключения

- **T-003** требует решения владельца (форма модели `FormStep`) — вставить решение прямо в промпт S3, иначе агент угадает.
- **T-051** не входит в поток до появления пакета preview (Q-8 закрыт: пакет будет, задача ждёт).
- **Q-1** (кнопки 3–4 тулбара) — заглушки, не возвращаться без решения владельца.
- **Q-3** (контракт микрофронтенда) — вне скоупа сессий S1–S15.
