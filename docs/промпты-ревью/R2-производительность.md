# R2 — производительность канваса

Контекст: `docs/ревью-архитектуры-2026-10-13.md` (раздел 3, A4). Стенд: `/stress.html#/editor`
(121 узел, 1105 карточек). Сейчас: загрузка 30 с, выделение карточки 3.3 с, символ в
атрибутах 3.2 с, любая команда 3.5–4 с. Цель: выделение < 100 мс, команда < 300 мс,
загрузка < 5 с.

Причины (замерено профилем):

- любое изменение графа/размеров → `graphToFlow` пересоздаёт все узлы → кэш в
  `use-editor-graph.ts` промахивается → ререндер всех узлов, карточек, рёбер;
- петля измерений: `reportNodeSizes` → `computeLayout` → новые узлы → новые измерения
  (44 раскладки на загрузке);
- `FormNode` зовёт `updateNodeInternals` на каждое новое `data.steps`;
- в `data` узлов вшиты колбэки и выделение (onSelect, selected, connectTarget…).

Сделать (по убыванию эффекта, замеряя после каждого шага):

1. Структурное разделение в `graphToFlow`: неизменённая страница (тот же объект immer) →
   тот же объект узла; позиции отдельно от `data`.
2. Раскладка по измерениям — один проход за кадр; пересчёт, только если изменилась
   высота/ширина колонки.
3. Выделение, цель связи, обработчики — не через `data`: контекст действий +
   подписка по селектору (`useSyncExternalStore`); `ElementCard` в `React.memo`.
4. `updateNodeInternals` — только при смене набора handles.
5. Панель атрибутов: локальный буфер поля, команда по blur/debounce 300 мс.
6. Если мало — `onlyRenderVisibleElements` у ReactFlow.

Поведение не меняется. Проверка: `npm run verify`, `npm run rules`, `npm run ui` по
выделению/dnd/связям на демо; замеры на стенде — в ответе таблицей «было/стало».
