## 1. Что это за проект

**blueprint-studio** — автономный визуальный редактор архитектурных карт
(`ServiceBlueprint`) для описания микроприложений на движке **lib-app-core**.
Пользователи: архитекторы и разработчики. Выходной артефакт: версионируемый JSON
(`MicroAppDescriptor`, генератор — Epic 005, ещё не начат).

**Форма поставки [решение владельца, 2026-10-06]:** микрофронтенд — remote module
(Module Federation), встраивается в существующее host-приложение на Rsbuild.
Сейчас приложение работает standalone; MF ещё НЕ настроен, но код не должен
создавать препятствий для него (см. конституцию §7: динамический import в
`index.tsx`, никаких записей в `window`, относительные пути, scoped-стили).

## 4. Стек (менять состав запрещено без решения владельца)

Rsbuild 2.2 (+SWC, **не Vite**), React 19.3, TypeScript 5.7 strict,
UI-кит `@sber-friend/flamingo-components` 4.9.17 (весь UI только из него,
включая иконки; цвета только из темы, литеральные hex запрещены),
zod 4.6, immer 11.1 (`produceWithPatches` — единственный механизм мутации),
awilix 13.0 (DI, только `InjectionMode.PROXY` + деструктуризация в
конструкторах), react-router-dom 7.18 (`createHashRouter`),
vitest + testing-library, ESLint flat + `eslint-plugin-boundaries`,
Prettier + Husky + commitlint + lint-staged.
**Запланировано, но НЕ установлено:** @xyflow/react (canvas, Epic 002),
effector+patronum (presentation), xstate (Epic 004).
**Осознанный отказ:** Vite/Next/CRA, Redux/Zustand, декораторы DI.

Версии фиксируются точно (`npm install -E`, без `^`). Пакеты `@sber-friend/*`
тянутся из внутреннего registry — без доступа к нему `npm install` не пройдёт.

## 5. Архитектура (4 слоя, enforced eslint-plugin-boundaries)

```
src/
├── domain/          # чистый TS: zod-модель + инварианты. Ноль внешних импортов
├── application/     # порты (интерфейсы) + команды (CommandBus)
├── infrastructure/  # адаптеры портов + composition root (container.ts)
└── presentation/    # React: app, pages (project-list / editor / preview)
```

Направление зависимостей: `domain → application → infrastructure → presentation`.
Нарушение не проходит lint.

**Железные правила (конституция §3, кратко):**
1. Любое действие пользователя — команда application-слоя через `CommandBus`
   (execute/undo/redo на `produceWithPatches`). UI не мутирует состояние напрямую.
2. Внешние контракты — только за портами из `application/ports`.
3. Один DI-контейнер: `buildContainer()` в `bootstrap.tsx`, Awilix PROXY.
4. Домен не знает о React/zod-рантайме вне схем/effector/awilix/xyflow/Flamingo.

## 7. Рабочий процесс (как сюда попал код и как продолжать)

1. **Одна сессия = 1–2 задачи** из декомпозиции, по графу зависимостей.
   Реализуешь ТОЛЬКО перечисленные задачи. Решения D1–D13 и ADR не обсуждаются:
   если код противоречит решению — неправильный код.
2. После каждой задачи: `npm run test && npm run lint && npm run build` —
   всё зелёное. Запрещено ослаблять tsconfig/eslint ради прохождения.
   Реально запускай команды и прикладывай фактический вывод (конституция П5).
3. Каждая сессия заканчивается коммитом (conventional commits, commitlint).
4. Приёмка: `/check-state` (read-only аудит PROJECT_STATE vs репо) →
   приёмка по критериям задачи → `/update-state` (запускает только владелец).
5. Контекст между сессиями переносит `PROJECT_STATE.md` — читай его, а не
   историю прошлых чатов.

**Стоп-условия (немедленно остановиться и доложить владельцу):** конфликт
peer dependencies; пакет не найден в registry; публичный API пакета отличается
от ожидаемого в спеке; задача требует изменения конституции. По стоп-условиям
запрещены `--force` / `--legacy-peer-deps` без явного разрешения владельца.
