# 000 — Конституция проекта blueprint-studio

> **Статус:** действующая. **Приоритет:** высший. При конфликте любой другой спеки, задачи или предложения агента с этим документом — побеждает этот документ.
> Этот файл обязан находиться в контексте агента при выполнении ЛЮБОЙ задачи (в system prompt, AGENTS.md или эквиваленте).

---

## 1. Продукт одной строкой

**blueprint-studio** — автономное React-приложение (класс «native» по внутренней классификации), визуальный редактор архитектурных карт (`ServiceBlueprint`) для микроприложений на движке lib-app-core. Узлы на canvas — визуальные заглушки компонентов; их атрибуты и ограничения подтягиваются из пакета `element-schemas` (lib-app-core). Выходной артефакт — версионируемый JSON.

## 2. Глоссарий (обязателен)

Идентификаторы в коде — ТОЛЬКО осмысленный английский. Запрещены: транслит (`karta`, `szenariy`), русские аббревиатуры (`Mip`, `MIP`, `KE`), сокращения внутренних терминов. Русский язык — только в UI-строках и документации.

## 3. Архитектурные слои

```
src/
├── domain/          # чистый TS. НОЛЬ внешних импортов (включая React, zod — только в schemas/)
├── application/     # use-cases (команды), порты (интерфейсы), IR-конвейер
├── infrastructure/  # адаптеры портов, composition root (DI-контейнер)
└── presentation/    # React + Effector: pages, features, widgets
```

### Правила зависимостей (проверяются линтером, нарушение = брак)

| Слой             | Может импортировать                                                           | НЕ может импортировать                                                               |
| ---------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `domain`         | только внутри `domain`                                                        | ВСЁ внешнее: React, reactflow, Flamingo, Effector, Awilix, XState                    |
| `application`    | `domain`                                                                      | React, reactflow, Flamingo, `infrastructure` (только порты объявляет, не реализации) |
| `infrastructure` | `domain`, `application`                                                       | React, reactflow, `presentation`                                                     |
| `presentation`   | `domain`, `application`, `infrastructure/container` (только composition root) | конкретные адаптеры из `infrastructure` напрямую                                     |

### Железные правила

1. **Любое действие пользователя — команда application-слоя.** UI не мутирует состояние напрямую. Каждая команда возвращает пару патчей (do/undo) через `produceWithPatches` из Immer — это же основа undo/redo и будущего версионирования.
2. **Внешние контракты — только за портами.** `element-schemas` (lib-app-core), хранилище, файловый экспорт — доступны фичам только через интерфейсы из `application/ports`. Адаптер нормализует чужой формат в наш внутренний.
3. **Права ролей проверяются в use-case** (guard), UI лишь отражает разрешённое. Скрытая кнопка ≠ защита.
4. **Новый формат экспорта = новая реализация `IMicroAppDescriptorGenerator`.** Существующий код конвейера не меняется (Open/Closed).
5. **Hard rules (раздел 4) — доменные валидаторы**, а не проверки в обработчиках кнопок.
6. **Один DI-контейнер**, создаётся явно вызовом `buildContainer()` в `bootstrap.tsx`. Запрещён импортируемый синглтон-контейнер.
7. **Awilix — только `InjectionMode.PROXY`** и конструкторы с деструктуризацией (`constructor({ projectRepository })`). Причина: минификация production-сборки переименовывает параметры конструктора, CLASSIC-режим ломается только в проде. Имена свойств в деструктуризации минификатор не трогает.

## 5. Фиксированный стек

## 6. Правила имён и кода

- Файлы: `kebab-case.ts(x)`. Классы/типы: `PascalCase`. Функции/переменные: `camelCase`.
- Порты: префикс `I` (`IProjectRepository`). Адаптеры: говорящее имя (`IndexedDbProjectRepository`).
- Запрещены: `any` (кроме точечного с `// eslint-disable` и комментарием-причиной), `@ts-ignore`, закомментированный код, `TODO` без номера задачи.
- Комментарии — на русском, только «почему», не «что».

## 7. Гигиена встраиваемости (MF-readiness, без MF)

MF НЕ настраиваем. Но запрещено создавать препятствия к нему:

1. Entry: `src/index.tsx` → только динамический `import('./bootstrap')`; монтирование React — в `bootstrap.tsx`.
2. Никаких предположений о корневом пути: роутинг и ассеты — относительные / через base path из конфига.
3. Запрещено писать в `window`/global scope, запрещены глобальные CSS-селекторы; стили — scoped (CSS Modules или стилизация Flamingo).
4. React/react-dom — прямые фиксированные зависимости (легко пометить `shared` в будущем).

## 8. Протокол работы агента (анти-выдумки) — ОБЯЗАТЕЛЕН

- **П1. Проверяй, не предполагай.** Перед использованием любого API библиотеки (Flamingo, reactflow, Effector, XState, Awilix) — посмотри его в установленной версии: `node_modules/<pkg>/dist/*.d.ts`, README пакета, экспорты через `node -e "console.log(Object.keys(require('<pkg>')))"`. Запрещено использовать API «по памяти».
- **П2. Нет данных — стоп.** Если для задачи не хватает информации (формат, версия, доступ) — ОСТАНОВИСЬ и сформулируй вопрос владельцу. Запрещено додумывать контракты, особенно формат `element-schemas` и `MicroAppDescriptor`.
- **П3. Одна задача — один атомарный шаг.** Не выполняй следующую задачу, пока текущая не прошла критерии приёма. Не рефактори «заодно» код вне задачи.
- **П4. Верификация после каждой задачи:** `npm run lint && npm run build` — обе зелёные. Падающую проверку чинить, а не обходить (запрещено ослаблять tsconfig/eslint ради прохождения).
  **[Решение владельца 2026-10-10]: unit-тесты НЕ пишутся и НЕ запускаются.** Новый код поставляется без тестов; полный `npm run test` не выполняется. Исключение — точечный прогон (`npx vitest run <файл>`) только когда изменён ранее написанный код, у которого уже есть тесты: тогда затронутые тестовые файлы чинятся (фикстуры/ожидания) и прогоняются точечно. Уже существующие тесты в репо не удаляются. Это решение отменяет все требования «unit-тесты» в текстах задач, декомпозициях и промптах сессий.
- **П5. Реально запускай команды.** Запрещено писать «команда должна сработать» — запусти и приложи фактический результат. Если команда не запустилась — это часть отчёта.
- **П6. Не выдумывай версии.** Установка только `npm install -E <pkg>` и фиксация фактической версии. Запрещено вписывать версии в package.json «из головы».
- **П7. Стоп-условия (немедленно остановиться и доложить владельцу):** конфликт peer dependencies; пакет не найден в registry; публичный API пакета отличается от ожидаемого в спеке; задача требует изменения этой конституции. По стоп-условиям запрещено применять `--force`/`--legacy-peer-deps` без явного разрешения владельца.
- **П8. Не создавай файлы вне плана задачи.** Каждый новый файл должен быть перечислен в tasks.md или согласован.
- **П9. Отчёт по задаче:** что сделано, какие файлы созданы/изменены, вывод верификации (П4), отклонения от плана (если есть — с причиной).

## 9. Definition of Done (любой задачи)

1. Критерии приёма задачи выполнены — все, не частично (требования «unit-тесты» в критериях отменены [решение владельца 2026-10-10, §8 П4]).
2. `lint` (включая `tsc --noEmit`), `build` — зелёные.
3. Правила слоёв не нарушены (boundaries-линтер молчит).
4. Новые зависимости — только из списка задачи, версии зафиксированы точно.
5. Отчёт по П9 написан.
